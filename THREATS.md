# Threat Modeling & Defense Matrix (THREATS.md)

This security specification documents the threat model, attack vectors, systemic impacts, architectural defenses, and automated verification tests implemented for the **Snovasys Secure Money Transfer and Transaction Integrity System**.

---

## 1. Security Design Principles

1. **Zero Client Trust**: All user identifiers, account numbers, and roles are extracted strictly from the authenticated server-side security context (`SecurityUtils.getCurrentUserId()`), never accepted from client request bodies or query parameters.
2. **Pessimistic Concurrency Control**: Account records are locked using `LockModeType.PESSIMISTIC_WRITE` (`SELECT ... FOR UPDATE`) before any balance check or mutation occurs.
3. **Deterministic Deadlock Prevention**: Resource locks across multiple accounts are always acquired in strictly sorted ascending order by primary key (`Math.min(senderId, receiverId)` followed by `Math.max(senderId, receiverId)`).
4. **Conservation of Balance**: Every debit is atomically balanced by an equivalent credit within an active database transaction (`@Transactional(isolation = Isolation.READ_COMMITTED)`).
5. **Exact Arithmetic Precision**: All financial amounts utilize `java.math.BigDecimal` with explicit scale (4 decimal places) and `RoundingMode.HALF_UP`.
6. **Idempotency Guarantee**: Every state-changing transfer requires a client-supplied unique UUID key, checked and enforced at both the database level (unique constraint) and application level.
7. **Immutable Audit Trail**: Audit records are stored in an append-only log table where database privileges prohibit `UPDATE` and `DELETE`. Audit logging uses `Propagation.REQUIRES_NEW` so failed attempts are permanently recorded even if the business transaction rolls back.

| **THR-01** | **A01:2021 &mdash; Broken Access Control (IDOR)** | Insecure Direct Object Reference on account balance and profile endpoints. | Attacker supplies another victim's `accountId` or `userId` in API parameters to read their financial balance. | Unauthorized data disclosure, breach of financial confidentiality. | `UserService.java` & `UserController.java`: Ignores client IDs. | **THR-02** | **A04:2021 &mdash; Insecure Design (Double Spending / Race Condition)** | Simultaneous concurrent transfer requests exploiting race conditions between balance read and balance deduction. | Attacker with $100 balance submits 5 simultaneous $100 transfers across parallel threads within milliseconds. | Account balance drops into negative; bank loses $400 in unauthorized funds. | `TransferService.java`: Locks sender and receiver rows with `@Lock(LockModeType.PESSIMISTIC_WRITE)` (`findByIdWithLock`), followed by `entityManager.refresh()`. | **THR-16** | **A04:2021 &mdash; Insecure Design (Deadlock during Concurrent Cross-Transfers)** | User A transfers to User B at the exact same instant User B transfers to User A. | Thread 1 locks Account A and waits for Account B; Thread 2 locks Account B and waits for Account A. | System deadlock (`DeadlockLoserDataAccessException`), hung threads, transaction timeout and rollback. | `TransferService.java`: Deterministic lock ordering. ## 3. Defense Verification Summary

All listed defenses are continuously verified through our automated JUnit 5 and Spring Boot Test suite:

- **21 Automated Security Tests**:
  - `AuthenticationSecurityTest` (4 tests): JWT token issue, validation, rejection of tampered tokens, credential validation.
  - `AuthorizationSecurityTest` (5 tests): IDOR prevention, role separation, unauthorized endpoint blocking, profile isolation.
  - `TransferSecurityTest` (8 tests): Negative balance prevention, zero amount rejection, negative amount rejection, self-transfer block, non-existent account block, inactive account block, idempotency enforcement.
  - `TransferConcurrencySecurityTest` (1 test): Multithreaded race condition simulation with 5 parallel threads attempting double-spending.
  - `AuditSecurityTest` (3 tests): Verification of immutable audit records, failure event capture, and independent transaction commitment.

**Automated Test Execution Command**:
```powershell
mvn test
```
